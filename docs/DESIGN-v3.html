grit 设计修订 3 · 方案定稿 · 2026-10-14

分层组合：grit 变成「叠在 opencode 之上的一层纪律」

目标运行时 = opencode v2。主轴：不再用 grit 的 agent 正文「替换」opencode 的提示词，而是让 grit 的纪律「追加」在 opencode 原生层之上；续跑做减法（模型自判完成）。

opencode v2.0.25 源码 + 官方文档 生态调研（slim / OmO / 轻派共识） 保留：弱管强 · 省 token · 会话交接
00

30 秒结论

  • 病根：grit agent 正文落在 agent.system → 整段替换基础提示词、跳过 provider 变体、丢工具指导。
  • 药方 = 分层组合：原生层不动；grit 纪律改为运行时钩子追加；agent 定义薄覆盖（不写 system）。
  • 续跑（ULW）做减法：不重做 todo；判活只看"激活 + 未声明完成 + 护栏"；完成由模型自己按目标判断——不引入判据库、无独立验证、不用专家验证。
  • 保留既有机制：契约注入、会话交接、profile 引擎、token 快照、五个工具、命令、校准段。
  • 注入格式：一律用独立、带标签的块 / 合成消息，不拼进用户原文。
三个之前看不懂的词：
触发器
一个"事件时点"。grit 监听会话空闲（模型说完、没有正在跑的工具/子代理）这一时刻，到点才检查"要不要接着推"。不是定时轮询，也不是每步都查。
续跑判定
到点后判"继续 / 停止"。只有三条：未激活→不动；已激活且未声明完成→推一把；模型声明完成→停。
判据库（已删除）
早期草案那张"每条完成条件 + 证据 + pass/fail 状态"的表（即"仲裁文件"）。本设计不引入——它把复杂流程塞回上下文，违背省 token 与"让模型自己判断"。

03

设计依据（外部证据）

todo 为什么被删、还需不需要？决定续跑形态

官方唯一解释（维护者 issue #42421）："we removed it because it slows agent down and we haven't noticed significant performance improvements"；issue 已 reopen。

同类动作：Claude Code 在 Opus 4.8 / Sonnet 5+ 默认禁用 TodoWrite，理由"新模型内部自跟踪状态"+"工具定义与提醒占用上下文"。

三方确认 v2 无 todo：官方 tools 文档、opencode-todolist、zenox。

结论：新一代模型下外部 todo 工具被认为多余甚至拖慢 → grit 不重做 todo 工具。

05

四个机制 + handoff + 工具面

B · 持续工作续跑（简化：无 todo、无判据库、模型自判完成）本轮重点

目的：/ulw 激活后，若模型一轮结束停下但目标未完成，自动推一把，直到它自己判断完成或触发护栏。

触发器：会话空闲这一时点（模型说完、无正在跑的工具/子代理）。

续跑判定（继续 / 停止）：① 未激活 → 不动；② 已激活且未声明完成 → 护栏允许时注入一句"继续推进该目标"（带目标）；③ 模型声明完成（整行标记 [grit:done:v1]）→ 停。完成由模型根据目标自行判断。

护栏（兜底）：2s 倒计时 · 冷却退避 · 失败上限 · 注入预算 · abort 窗口 · 上下文超限跳过 · 用户打断暂停 · 工具死循环（warn3/block5）· 指纹未变即停。

状态：仅 grit/state/<sid>.json 最小集（active / goal / 计时 / 计数）。无逐条判据、无证据账本、无独立验证器。

为什么简化：验证不与执行分离、不用专家（浪费）；模型按目标自判完成足够。旧版靠"扫 todo"判活，v2 已无此工具；新版不依赖任何外部清单。
A · 契约注入（/ulw）保留 · 微调

/ulw 触发 → 注入模式块（场景契约/双证据/审查门/MANUAL QA/零容忍/完成判定/交接阶梯）一次（持久）；context 钩子负责压缩恢复 + 每轮一行标记（非持久）。注入格式改为独立块/合成消息（§6）。

C · profile 引擎 + 校准保留 · 收缩

热参数 / 3s TTL / profile 工具不变；promptVariants 降为纪律段级。校准：以 provider/model 作用域 context 钩子追加极短校准段（glm/deepseek/default）——v2 官方唯一自定义途径，且 v2 不覆盖这两个模型族。

D · token 快照 + handoff + 工具面

D 事件源在位。handoff（会话交接）：session.create + session.prompt + 本会话置停；模板单一来源 contracts/handoff-template.md。工具面维持 5：context_usage · system_time · clone_repo · handoff · profile（不新增 todo）。

06

注入格式规范（本轮修正）

原则：任何 grit 注入都用独立、带标签的块；绝不拼进用户原文、绝不当成用户说的话。

两种载体：① 系统提醒块 <system-reminder>…</system-reminder>（用于每轮标记）；② 独立合成消息 ctx.session.synthetic({sessionID, text, resume:false})（用于模式激活与续跑提示）。

标签命名：统一 <grit:…> 命名空间 + 首尾哨兵，例：<grit:ulw-mode v1>…</grit:ulw-mode>、<grit:continue v1>…</grit:continue>、<grit:done v1>…</grit:done>。

为什么改：OmO 把用户信息与注入都包成块，模型能区分"用户在说"与"harness 在说"；grit 旧做法（text + "\n\n" + appended 拼进用户消息）混淆来源 → 改为块/合成消息。

缓存纪律：只追加尾部块 / 一条尾随易变消息，永不改写已缓存前缀。

分阶段实施计划

  1. 实验先行（V-2/V-3/V-4/V-7/V-8）。未过不改架构。
  2. 纪律段抽取（去 todo 依赖、加"完成纪律"）+ 校准段（provider 作用域）。
  3. 薄覆盖落地（合成 agents 记录；删 agents/*.md；explore 放行 clone_repo）。
  4. 追加通道（按 event.agent / providerID 追加，独立块）。
  5. 机制 B 简化（激活 + 未声明完成 + 护栏；删 todo 依赖与判据库残留）。
  6. plan 回归原生（删自建 plan 子代理 + 更新 build 路由表 + costRatio）。
  7. 注入格式落地（合成消息 / 标签块，替换字符串拼接）。
  8. harness 更新 + 验证矩阵全过 + 重新部署。
  9. 文档重写（README 补 browse、消除模板双写与计数漂移）。

每阶段验收证据（R13/R14）：真实执行痕迹。
