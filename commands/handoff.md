用户手动指令 /handoff：立即交接本会话。不要询问、不要确认、不要继续其他工作。

1. 按下方模板立即撰写完整交接摘要（所有内容从当前对话提取，禁止编造）。
2. 调用 `handoff` 工具，把摘要作为 summary 参数传入。
3. 工具返回成功后本会话终止：不再执行任何任务；若被再次唤醒，只回复"本会话已交接并结束，请在新会话中继续。"

【交接摘要模板】（调用 handoff 工具时作为 summary 参数传入）

写法要求（三条）：
- 以「信息够全」为唯一标准——宁可写细，也不要让下一个会话把已知的东西重新查一遍。
- 只陈述**信息**（是什么 / 在哪 / 结果如何 / 还差什么 / 卡在哪），不写**指令**（"必须先…""务必…""去做 X"）；怎么做由下一个会话自己判断。
- 具体到可核对：路径写全、命令贴原文、输出给关键行、报错给原文、版本与配置给实际取值。

## 1. 任务与目标
（这件事是什么；目标＝用户最近一次提出的那件事；若同时存在更早的全局目标，说明与它的关系、是否冲突）

## 2. 当前状态
（进行到哪一步：已完成的 / 正在做的 / 尚未开始的；最后一个动作是什么、结果如何）

## 3. 已确认的事实（无需重新探索）
- 方案与决定：…（连同为什么这样定、否掉了哪些备选、原因）
- 已验证的结论：…（用什么命令/测试得出的、输出关键行）
- 关键文件：绝对路径 + 作用 + 相关行号
- 环境事实：版本号、路径、环境变量、配置项的实际取值
- 外部依据：文档/源码出处（文件:行 或 链接）

## 4. 待处理的工作
（以信息形式写"还差什么"：X 尚未完成，现状是…，卡在…；不要写成"去做 X"）

## 5. 已知的坑
（踩过的报错原文 + 触发条件 + 结论/绕法；依赖、权限、环境限制；没有写"无"）

## 6. 验证情况
（已验证的：判据 + 真实证据（命令/输出/文件）；未验证或无法验证的也逐条列出，跳过的明说）

## 7. 会话级状态
（未落盘的改动、未提交的文件、临时文件/进程/端口及其位置、状态文件路径与取值、下一个起点在哪）
